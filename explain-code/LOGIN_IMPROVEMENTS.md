# สรุปการปรับปรุงหน้า Login (แยกตาม Role)

ไฟล์ที่แก้: `app/page.tsx`

## ที่ปรับ (ทั้งสอง Role)
- เอาค่าเดโมที่เติมไว้ล่วงหน้าในช่องกรอกออก (ชื่อเล่น, PIN, รหัสห้อง, รหัสผ่านครู)
- เพิ่มสถานะ `isSubmitting` ผ่าน `runSubmit`: ปิดปุ่มระหว่างส่งข้อมูล และแสดง "กำลังตรวจสอบ..." เพื่อกันกดซ้ำ
- จับ error เครือข่ายและแสดงข้อความแทนการค้างเงียบ ๆ

## นักเรียน (student)
- ช่อง PIN รับเฉพาะตัวเลข (`inputMode="numeric"`, `autoComplete="off"`)
- ปุ่มบัญชีตัวอย่าง (PIN 1234) ยังใช้กรอกให้คลิกเดียวได้

## ครูผู้สอน (teacher)
- ปุ่ม "แสดง/ซ่อน" รหัสผ่าน
- `autocomplete` ถูกต้อง: `username`, `current-password` (เข้าสู่ระบบ), `new-password` (สมัคร)
- ข้อความแนะนำรหัสผ่านอย่างน้อย 4 ตัวอักษรในโหมดสมัคร
- ปุ่ม "ใช้บัญชีครูตัวอย่าง" แทนการแสดงรหัสผ่านเป็นข้อความในหน้า

## ปัญหาความปลอดภัยที่พบ (ยังไม่ได้แก้)
| ปัญหา | ตำแหน่ง | ข้อเสนอแนะ |
|---|---|---|
| ครูล็อกอินได้โดยไม่ตรวจรหัสผ่านเมื่อไม่ได้ตั้งค่า Supabase (API ตอบ `authenticated: true` เสมอ การตรวจเกิดฝั่ง client) | `app/api/auth/route.ts` | ย้ายการตรวจสอบมาไว้ที่ server |
| Session เก็บใน `localStorage` แก้เองได้ | `app/page.tsx` | ใช้ httpOnly cookie ที่ server เซ็น |
| แฮชรหัสผ่านด้วย SHA-256 ล้วน ๆ | `app/api/auth/route.ts` | ใช้ bcrypt หรือ argon2 พร้อม salt |
| PIN 4 หลักเดาง่าย | `app/api/auth/route.ts` | เพิ่ม rate limit / lockout |

## การตรวจสอบ
- `npx tsc --noEmit` ผ่าน ไม่มี error
- ยังไม่ได้ทดสอบหน้าจริงในเบราว์เซอร์
